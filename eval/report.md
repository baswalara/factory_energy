# Evaluation report

Generated by `python scripts/run_eval.py`. LLM setting for this run: **mock**.

**Method.** Exact match with a stated tolerance; no LLM judge. Answer types must match exactly. Numeric answers are compared with values recomputed in the evaluation script from the raw CSV files using plain pandas (tolerance shown per case in `eval/cases.json`). The bill split is compared with the split planted by the data generator (`eval/truth.json`), which the application never reads.

**Read this first.** The data is our own synthetic data, built from the same kind of model the baseline assumes (energy linear in units and degree-days, plus a cooling effect that depends on whether the day is a working day, and random day-to-day noise). Scores on it are therefore optimistic. They show the code is correct and how it behaves under noise; they do not predict accuracy on HCLTech's hidden data.

Without product mix, the mix shift cannot be separated: it is reported as waste, which blames machines for a change in what was made. That is the reason we keep the per-product baseline even though its rates are less precisely estimated.
